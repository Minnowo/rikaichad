# Milestone 6 work list

A web UI embedded in the binary and served by `jisho serve` (docs/brief.md:
"web UI later on same server"; "HTML comes with the web UI").

## Decisions (user, 2026-11-10)

- Build: TypeScript (tsc only, no bundler) and Tailwind v4 with the
  ponkotsu-css base style and palette (https://github.com/Minnowo/ponkotsu-css,
  default seeds). Sources in ui/src; `npm run build` writes ui/dist, which
  is committed and embedded with include_bytes!, so `cargo build` needs no
  Node. check.sh rebuilds ui/dist and fails if the committed copy is stale
  (skipped with a notice when npm is not installed).
- Glossaries: structured content rendered to HTML in the browser (port of
  Yomitan's StructuredContentGenerator: same tags and class names, DOM API
  only, no innerHTML), with each dictionary's styles.css scoped to its
  definitions like Yomitan (Yomitan nests it in
  `[data-dictionary="title"] { ... }`; jisho uses
  `[data-dictionary-id="N"]`). The CSS is parsed by the browser first, so
  unbalanced braces cannot escape the scope; nesting selectors can still
  reach the definition item and its siblings (as in Yomitan), and paint
  is contained per definition.
- Screens: word lookup, kanji lookup, sentence parse. No dictionary
  management screens (the CLI and API cover them).
- Theme: ponkotsu's default seeds; light and dark follow the system.

## API additions

- `GET /v1/dictionaries/{id}/styles`: the dictionary's styles.css as
  `text/css` (404 when it has none).
- Headwords in term lookups carry `furigana` (segments as in parse), so
  clients do not need their own furigana port.
- A request whose `Origin` is the server's own (`http://` or `https://`
  + its `Host` header, which is already checked) is allowed without being
  in `allowed_origins`: the UI's own fetches. Only when the Host cannot be
  a rebound DNS name: a loopback name, an IP literal, or a name in
  `allowed_hosts` (a wildcard bind otherwise accepts any Host; found in
  review).

## Serving

- `GET /` is the UI page; `GET /ui/<file>` its assets. Fixed set, built
  into the binary. Headers: Content-Security-Policy (`default-src 'none'`,
  scripts, styles, fetches from `'self'` only, no frames), nosniff,
  `Cache-Control: no-cache`.
- External resources in dictionary CSS or structured-content styles
  (`url(...)`) are blocked by the CSP; jisho has no media.

## Review (independent reviewer, 2026-11-10)

1. Same-origin rule let DNS rebinding through on a wildcard bind without
   `allowed_hosts` (any Host accepted, so a rebound name could match its
   Origin): fixed, test `rebinding_on_a_wildcard_bind_is_not_same_origin`
   failed first.
2. `npm run build -- --out` with an empty value or ui/ deleted ui/: the
   build refuses empty values, ui/ and its ancestors, and anything inside
   ui/ but dist.
3. Leaving a page did not cancel its pending search, which could rewrite
   the URL of the next page; a re-parse did not abort the previous parse
   or word lookup: pages get a signal aborted on navigation, and parse
   aborts its older requests.
4. Scoped dictionary CSS can still reach the definition item and its
   siblings through nesting selectors (as in Yomitan): documented; paint
   is contained per definition (`contain: paint`).
5. Docs out of date (scope attribute, https, install.md origins, proxy
   Host): fixed.
6. Test gaps (https, case, wildcard bind, read-only, whole CSP): tests
   added.
7. Port differences (dataset values, external-link icon): now as in
   Yomitan; images stay a text placeholder (no media), noted in the file
   header.
8. Doc comments added; check.sh checks the license header of ui/src CSS
   files too.

Not done: there are no automated tests of the TypeScript (no JS test
runner; the renderer was checked in a headless browser, see below), and
check.sh runs `npm ci` only when ui/node_modules is missing, so a
node_modules older than package-lock.json is not refreshed.
